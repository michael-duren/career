# Career releases

Commit and push this workflow and its helper/tests to main before creating a new stable numeric tag (`v1`, `v1.2`, or `v1.2.3`). Old tags do not acquire new workflows. A `v*` tag push or published non-prerelease GitHub Release runs `.github/workflows/release.yml`. The gate rejects suffixes, deleted tags, moved tags, and commits outside `origin/main`; the exact event commit must match the peeled tag. No main push deploys.

The workflow tests the tagged frontend and Go source, builds assets, and runs the HTTP integration test against disposable Postgres 17 before publishing the root Dockerfile for linux/amd64. GHCR uses `GITHUB_TOKEN` with Packages write. Configure the repository Actions secret `HOME_INFRA_DISPATCH_TOKEN` with Actions write on `michael-duren/home-infra`. It is separate from the infra repository's `SOURCE_READ_TOKEN`, which needs Contents read on private source repositories for verification. No application secrets, LAN credentials or kubeconfig enter Actions.

The canonical image is `ghcr.io/michael-duren/career:sha-<full-source-sha>`, with OCI source and revision labels. Duplicate tag/release events reuse its verified digest instead of rebuilding. Registry authentication/network failures fail closed; only an explicit manifest-not-found response permits a build. Do not delete or overwrite canonical SHA tags, and restrict package writers to this workflow. Both event types share one publishing concurrency group. GitHub can cancel an older pending run; rerun it if needed. A failed dispatch can be retried by rerunning the release job without changing the image.

Promotion calls `gitops-promote.yml` in `michael-duren/home-infra` at `main`, with string inputs `app=career`, `tag`, `sha`, and `images` containing `{"career":"ghcr.io/michael-duren/career@sha256:<digest>"}`. HTTP acceptance is not deployment success: inspect the home-infra workflow and gitops ledger. Initial app releases can seed the ledger before the first infra release. Argo adoption, private `ghcr-pull` provisioning, and existing runtime Secrets remain operator responsibilities. The release cannot deploy unreleased templates from infra main.

`scripts/deploy-homelab.sh build` remains a local image build, and `check` retains local validation (its integration check needs the existing development database). `deploy`, the default invocation, and `rollback` now fail before any cluster command. Use a reviewed GitOps rollback; database rollback is separate. For an emergency manual change, first deliberately suspend affected Argo sync and follow an operator-reviewed incident plan using a released digest snapshot. This script provides no automatic bypass. Reconcile the GitOps source before resuming sync.

Local release helper checks: `python3 -m unittest discover -s tests -p 'test_release.py' -v`. No credentials or registry calls are needed by these tests. Publication, cross-repository dispatch and live adoption must be verified after the user configures credentials and publishes the first release.
