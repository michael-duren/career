# Developer guide

Career is one Go service that serves the static Astro build and the `/api` routes, backed by
PostgreSQL. Leetgrinder pages are rendered on the server with templ.

## Prerequisites

- Node.js (see `.github/workflows/ci.yaml` for the CI version) and npm
- Go (version from `go.mod`)
- Docker with Compose v2

## Getting started

```sh
make dev
```

`make dev` installs dependencies, sets up `.env`, starts PostgreSQL, builds the frontend,
applies migrations, and starts the Go server. Open http://localhost:8080 and log in with
`admin` / `password123` if you accepted the local defaults.

`make start` does the same but skips steps that are already done, and also starts the local
observability stack (set `SKIP_OTEL=1` to skip it). Run `make help` for every target.

## Configuration

Run `npm ci` and `npm run setup` to create `.env`. Press Enter to use the local login
`admin` / `password123`, or answer `n` to choose a username and password. The script hashes
the password, generates a random JWT secret, and uses the local Docker Compose database
credentials. Existing `.env` files are kept. For no prompts, use `npm run setup -- --defaults`.
Copying `.env.example` also works, with the same login and a fixed development JWT secret.

`.env.example` documents every setting. The core ones are `APP_ENV`, `DATABASE_URL`,
`AUTH_USERNAME`, `AUTH_PASSWORD_HASH`, `JWT_SECRET`, `PUBLIC_ORIGIN`, `LISTEN_ADDR` and
`STATIC_DIR`. The Go executable reads `.env` without overwriting the process environment.
Development defaults are loopback-only. Production must supply the database URL, listen
address, username, public origin, bcrypt password hash and a non-placeholder JWT secret of at
least 32 characters.

Optional features have their own settings:

- Leetgrinder: `LEETGRINDER_SECRET_KEY`, `ANTHROPIC_API_KEY`, `LEETGRINDER_ANALYSIS_*` (see [Leetgrinder](leetgrinder.md))
- Weekly scheduler Google Calendar: `SCHEDULER_GOOGLE_*`, `SCHEDULER_SECRET_KEY` (see [Weekly scheduler](weekly-scheduler.md))
- Audio thought transcription: `RUNNING_TRANSCRIBE_ENABLED`, `WHISPER_*` (see [running notes deployment](../deploy/running/README.md))
- Metrics: `OTEL_*`

To generate a bcrypt hash without putting a password in shell history:

```sh
read -rs 'password?Login password: '
printf '%s' "$password" | go run ./cmd/api hash-password
unset password
```

Put the output in `.env` as a **single-quoted** `AUTH_PASSWORD_HASH` to preserve its dollar
signs. An unset development hash disables login; a malformed hash is a startup error.

## Running locally

### Database

```sh
make postgres-up migrate check-db
```

PostgreSQL binds only to `127.0.0.1:5433`, with database and user `career_dev` and the
local-only password `career_dev_local`. The named Docker volume persists across restarts and
`docker compose down`. A custom `POSTGRES_LOCAL_PORT` also needs a matching `DATABASE_URL`.

Startup fails with a clear error if migrations have not been applied; the server never changes
the schema or seeds data on its own. Run `make migrate` after pulling new migrations.

### Server and frontend

```sh
npm run build   # builds the Astro site into dist/
make go-dev     # applies migrations and serves on :8080
```

Go serves both the APIs and the static build from `STATIC_DIR`. `npm run dev` runs the Astro
dev server for frontend-only work; build and run Go to test authenticated API calls.
`make watch` runs Go with live reload via Air.

Leetgrinder templates are generated by `make generate` (`go tool templ generate`). `make dev`,
`make build` and Docker builds run it for you. Generated `*_templ.go` files are ignored, so
run `make generate` before `go test ./...` in a fresh checkout.

### Health checks

`/healthz` reports process liveness. `/readyz` checks PostgreSQL and schema compatibility and
returns 503 during a database outage without exiting. `/health` is a readiness alias.

### Observability

```sh
make otel-up   # Alloy (OTLP :4317) -> Prometheus (:9090) -> Grafana (:3000)
```

`make otel-up-local` and `make alloy-local` run the same stack with Alloy built on the host.

## Testing

```sh
make test           # Go tests
make test-postgres  # Go race tests against local PostgreSQL
npm test            # TypeScript unit tests and extension tests
npm run tc          # Astro sync and TypeScript check
npm run test:e2e    # Playwright against an already running server
```

Playwright does not start the app. Point it at a disposable, migrated workspace with
`TEST_BASE_URL` (default `http://127.0.0.1:4337`), `AUTH_USERNAME` and `TEST_AUTH_PASSWORD`.

Feature-specific suites:

- Leetgrinder extension: `cd extension/leetgrinder && node --test`
- Weekly scheduler: [testing the weekly scheduler](testing-weekly-scheduler.md)
- HTTP smoke test: `go build -o /tmp/career-migration ./cmd/api && node tests/go-api.integration.mjs`
  (uses port 8088 and temporary credentials, creates and removes one synthetic note)

CI (`.github/workflows/ci.yaml`) runs the Go, npm and Playwright suites on pull requests and pushes to `main`.

## Data import and export

```sh
(umask 077; go run ./cmd/api export > .migration-private/export.json)
go run ./cmd/api import --file <path> --source-store <store> --source-key <key> --source-revision '<etag>' --dry-run
```

Export streams the whole workspace as JSON under one consistent snapshot; check the exit status
before trusting it. `GET /api/export` does the same over HTTP but is bound by the 30-second
write timeout, so use the CLI for large backups. Export does not include audio clips, which live
only in PostgreSQL; keep database backups for a full restore.

Import only targets an **empty** workspace and rejects a populated one. Drop `--dry-run` only
for the intended target. It archives the source bytes in a private directory, validates every
entity, and writes everything in one transaction. `.migration-private/` is git-ignored.

`make rebuild-projections` recomputes book and company summaries from their Markdown.

## API

All routes except login and health checks require the session cookie. Mutations require the
exact configured `Origin` and a JSON content type.

- `POST /api/auth/login` with `{ "username", "password" }` sets an HttpOnly, SameSite=Lax
  cookie with a 24-hour lifetime. `GET /api/auth/verify` checks it; `POST /api/auth/logout`
  clears it. Login attempts are rate limited per peer address.
- `GET /api/entries/{kind}` lists (`limit`, `offset`) or reads one entry (`id`). `kind` is
  `note`, `document`, `personal`, `week`, `book`, `company` or `goal`.
- `POST /api/entries/{kind}` with `{ entry, revision }` saves; a null revision inserts.
  Mismatched revisions return 409.
- `DELETE /api/entries/{kind}` with `{ id, revision }` deletes.
- `POST /api/entries/{kind}/toggle` toggles a Markdown checklist item on a book or company.
- `POST /api/goals/steps/move` reorders or moves a goal step.
- `GET /api/agent-context`, `GET /api/search`, `GET /api/export`.

Leetgrinder, weekly scheduler, connections and audio thought endpoints are described in their
feature docs. The MCP endpoint is described in [MCP](mcp/README.md).

## Releases

Production runs on the homelab k3s cluster, managed by Argo CD from the `home-infra` repository.

1. Push a stable tag (`v1`, `v1.2` or `v1.2.3`) on a commit on `main`, or publish a release.
2. `.github/workflows/release.yml` verifies the tag, reruns the tests, publishes
   `ghcr.io/michael-duren/career:sha-<commit>`, and dispatches the image digest to
   `home-infra`'s `gitops-promote.yml` (needs the `HOME_INFRA_DISPATCH_TOKEN` secret).
3. `home-infra` writes the released manifests to its `gitops` branch, and Argo rolls them out.

Deployment templates live in `home-infra/k8s/apps/career-strategy`. Run `migrate` against
production before a release that adds migrations.

Locally, `make homelab-check` runs the release checks and `make homelab-build` builds the image.
Direct deployment and rollback are disabled to keep GitOps the only writer; roll back by
promoting an earlier tag.
